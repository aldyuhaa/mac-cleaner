# Mac Cleaner Project Brief

## Owner

Aldy Permana (`aldy_uhaa`) wants a local macOS cleaning app inspired by the premium structure of CleanMyMac, but built for personal use first.

## Product Goal

Create a native macOS utility that lets Aldy scan, review, and safely clean common junk files without repeatedly asking an AI assistant to run manual cleanup commands.

The app should feel polished and premium, with a left sidebar, colorful module pages, a prominent scan button, and clear safety labels before anything is removed.

## Primary Principles

1. Safety first: never delete sensitive files automatically.
2. User control: scan first, review results, then clean selected items.
3. Local only: no cloud sync, no external sending, no background data collection.
4. Useful before flashy: real scanning and cleanup matter more than visual effects.
5. Premium feel: visual direction can be inspired by CleanMyMac, but the product should have its own naming and personality.

## Current Technical Direction

Build as a native macOS app using SwiftUI.

SwiftUI is included with Apple's macOS SDK; it is not installed separately. The machine currently has Swift command line tools available. Full Xcode is needed later if Aldy wants a normal signed `.app` build workflow through `xcodebuild` or Xcode's Archive UI.

Current implementation builds successfully with `swift build` and can run with `swift run`, `Run Mac Cleaner.command`, or the generated local app bundle at `dist/Mac Cleaner.app`.

The local app bundle is generated by `scripts/package_app.sh`. It is ad-hoc signed for local testing, not notarized for public distribution.

## MVP Scope

The first working version should include:

1. Smart Care dashboard.
2. Cleanup scanner for safe user-level junk.
3. Applications page as a first-pass app inventory view.
4. Space Lens page for large folders/files overview.
5. Activity page for recent scans and cleanup actions.
6. Real scan of safe paths.
7. Results with size, path, category, and safety level.
8. Cleanup by moving selected items to Trash, not permanent delete.

Implemented additions after MVP foundation:

1. Cleanup results are grouped by category.
2. Activity log persists locally in Application Support.
3. Space Lens can scan the home folder or a chosen folder.
4. Space Lens shows largest direct child items with proportional bars.

## Initial Modules

### Smart Care

Dashboard showing summary cards:

1. Total junk found.
2. Cache found.
3. Trash found.
4. Logs found.
5. Last scan status.

Main action: `Quick Scan`.

### Cleanup

Find and review junk items from safe locations:

1. User cache: `~/Library/Caches`.
2. User logs: `~/Library/Logs`.
3. User temporary folder where safe and accessible.
4. Trash: `~/.Trash`.

Each result should show:

1. Name.
2. Category.
3. Size.
4. Path.
5. Safety label.
6. Selected/not selected.

### Applications

Early version:

1. List installed apps from `/Applications` and `~/Applications`.
2. Show app size.
3. Later: related leftovers in `~/Library/Application Support`, `~/Library/Caches`, `~/Library/Preferences`, and `~/Library/Logs`.

### Space Lens

Early version:

1. Scan home folder or selected folder.
2. Display largest folders/files.
3. Allow external SSD target such as `/Volumes/My Disk (aldy_uhaa)/`.

### Activity

Track:

1. Scan time.
2. Number of items found.
3. Total size found.
4. Cleanup time.
5. Number of items moved to Trash.
6. Total size moved to Trash.

## Deferred Features

Do not build these first unless specifically requested:

1. Malware removal.
2. Privacy scanner.
3. RAM booster.
4. System daemon cleanup.
5. Kernel/system-level cleaning.
6. Cloud cleanup.
7. Duplicate/similar image detection.
8. Scheduled background cleanup.

## Safety Rules

The app should default to these rules:

1. Only scan user-owned paths in the MVP.
2. Never touch macOS system directories like `/System`, `/bin`, `/sbin`, `/usr`, `/private`, or root-level `/Library` without a dedicated later permission design.
3. Never clean `~/Library/Application Support` automatically.
4. Move to Trash instead of permanent deletion.
5. Require confirmation before cleanup.
6. Mark browser cache as caution if browser is running.
7. Use explicit allowlists for cleanable paths.
